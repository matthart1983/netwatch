# NetWatch review — 2026-09-11

> Design/review record: this document can include proposals and revision-specific results.
> For current user behavior, use the [documentation index](index.md).

Reviewed at v0.30.4 (`9b4597e`, main). Six dimensions, five by independent
reviewers with file-level evidence, testing by hand. Every finding below was
read in the code; nothing is inferred from docs alone. Line numbers are as of
that commit.

**Verdict.** The differentiator is real and no neighbour has the combination:
process attribution, L7 decode with keylog decryption, a rule engine with
verified close, egress drift, and a sandbox, in one binary. The gaps are not
features. They are trust: the parts users lean on hardest are the least
verified, and the exposed surface is the least protected.

## 1. Crash and safety on the packet path

1. **QUIC Initial: slice start past end from one datagram.**
   `src/dpi/quic.rs:488-493` computes `payload_end = pn_offset +
   pn_plus_payload_len` and checks only `buf.len() < payload_end`, never
   `pn_plus_payload_len >= pn_len`. A zero length field indexes `buf[18..17]`
   and panics on the capture thread. No `catch_unwind`; `capturing` stays
   true while capture is dead.
2. **QUIC CRYPTO frame offset drives an unbounded `resize`.**
   `src/dpi/quic.rs:531-534`: `end = offset + length` with a 62-bit varint
   offset, then `out.resize(end, 0)`. Initial keys derive from the public
   DCID, so any sender forges a valid packet. An offset of 2^40 aborts the
   whole process through `handle_alloc_error`, not a thread panic.
3. **The sandbox covers the main thread only.** `src/sandbox/linux.rs:254`
   calls `restrict_self()` without `all_threads(true)`; the capability drop
   at `:87-89` is likewise per-thread. The capture thread is spawned at
   `src/app.rs:736`, before `sandbox::apply` at `:1742`, as are the tokio
   workers and the GeoIP thread. The thread that parses attacker bytes keeps
   CAP_SYS_ADMIN, CAP_BPF, and unrestricted filesystem access.
4. **A DPI panic freezes the connection table silently.** The capture thread
   locks `stream_tracker` through `safe_lock`
   (`src/collectors/packets/mod.rs:1474`), but the connections collector
   does `stream_tracker.lock().unwrap()` (`src/collectors/connections.rs:323`)
   and panics before `busy.store(false)` at `:395`, so `update()` short-
   circuits forever. The render path unwraps the same mutex at
   `packets/mod.rs:1880-1884` and takes the TUI down.
5. **Sandbox claims versus reality.** `src/sandbox/mod.rs:19-21` says TCP
   bind and connect are blocked; `linux.rs:3-9` admits they are not, and
   `apply_landlock` handles `AccessFs` only. `linux.rs:200-204` grants
   read-write on the current directory, so `sudo netwatch` from `~` makes the
   whole home directory writable, contradicting the "omit /home" claim at
   `:118-120`.
6. Smaller: `src/collectors/packets/dns_cache.rs:84-91` inserts into an
   unbounded map and unbounded channel per unique source IP and forks `host`
   per lookup; a spoofed-source flood inflates both. `src/dpi/http3.rs:313-
   328` decompresses gzip, zlib, and brotli with `read_to_end` and no output
   cap (needs keylog keys, so server-controlled only). 7 `SAFETY:` comments
   cover 31 `unsafe` blocks; the FFI edges in `tcp_info.rs`, `npcap.rs`,
   `pktap.rs`, and `sandbox/linux.rs` are uncommented, and
   `tcp_info.rs:519` walks a sysctl buffer by allocation size rather than
   returned length.

## 2. Diagnose over-claims

1. **Nine of 25 rules have no detector.** `iface.saturated` and
   `tcp.bufferbloat_local` have inputs hard-coded `None`
   (`src/diagnose/live.rs:174-175, 223`). `tcp.connect_failures`,
   `tcp.timewait_exhaustion`, `pmtu.blackhole`, `ipv6.broken`,
   `captive.portal`, `egress.drift`, and `egress.policy_violation` exist only
   in `rules.rs`. All 25 carry `RuleStatus::Active` (`rules.rs:47-292`) and
   `catalogue_label` prints "all active" (`:304-313`). The 0.30.0 changelog
   states the principle this violates.
2. **Hysteresis is declared and never read.** `consecutive_n`
   (`src/diagnose/detectors.rs:25`) has no consumer. Every rule fires on
   one sample.
3. **Four rules are high false-positive by construction.** `dns.failing`:
   one dropped probe out of three is 33% loss against a 5% threshold
   (`health.rs:452`, `detectors.rs:716`). `gateway.rtt_spike`: one
   instantaneous RTT against a sigma fed five duplicate readings per probe
   (`app.rs:867` every tick, `HEALTH_PROBE_TICKS=5`). `tcp.retrans_burst`:
   lifetime `total_retrans >= 5` (`detectors.rs:149`) reported as per minute
   (`:1470`), and verify compares the lifetime count so it cannot close
   while the socket lives. `tcp.bufferbloat_remote`: any socket with RTT
   over 100 ms and bytes sent for 30 s (`detectors.rs:155`).
4. **The one apply fix is blocked by netwatch's own sandbox.** The default
   Landlock ruleset lists `/etc/resolv.conf` read-only
   (`sandbox/linux.rs:142`); the backup goes to `/etc/…bak`
   (`remediation.rs:378`), so the fix reports "could not apply" unless
   `--no-sandbox`. On systemd-resolved hosts the write follows the symlink
   into the regenerated stub. On macOS writing `/etc/resolv.conf` changes
   nothing and reports "applied". `make_permanent` has no caller; the spec's
   `1-9`, `d`, `t`, `p` keys are absent. The journal and revert design
   itself (`remediation.rs:209-253`, `app.rs:917-936`) is sound and tested.
5. **Baseline.** "30 minutes" is 1800 ticks of duplicated readings, 360 real
   probes. The fingerprint is interface, gateway, resolvers, and /24
   (`baseline.rs:37-44`); no SSID or BSSID, so two hotspots on 192.168.1.1
   share a baseline and a VPN toggle costs 30 minutes each way. Three
   metrics are baselined (`live.rs:32-36`).
6. **Report and CLI.** `window_start == window_end == now`
   (`app.rs:5013-5015`); the timeline records opens only; driver, kernel,
   and qdisc are `None`; artifacts are a MAC-presence hack (`:5033-5036`).
   No non-interactive `netwatch diagnose`; the daemon has no engine
   (`main.rs:141-169`). Windows has no tcp_info and no wireless, so only the
   dns, gateway, and nat rules can fire there.
7. **Path rules.** The trace runs once at startup (`app.rs:1776`), never the
   specified 60 s re-trace; ASN is always `None` (`live.rs:253`); the
   `dns.slow_resolver` alternate-resolver, ICMP, and cached checks never run
   (`live.rs:421-424`), so cause ranking is degenerate.

## 3. Windows is English-only and shell-driven

| feature | Linux | macOS | Windows |
|---|---|---|---|
| interface stats | sysfs | `netstat -ibn` | PowerShell per tick, `netstat -e` fallback |
| interface info | sysfs + `ip addr show` per interface, UI thread | `ifconfig` + `networksetup` | `ipconfig /all` + `netsh` |
| default route | `ip route` | `route -n get` | PowerShell (0.30.4) |
| link speed | sysfs | `getifaddrs` | missing |
| wireless signal | `/proc/net/wireless` | missing | missing |
| process attribution | `ss` + `/proc`, eBPF | `lsof`, PKTAP | `netstat -ano` + `tasklist` |
| stable process name | `/proc/pid/exe` | `proc_pidpath` | missing |
| tcp_info | netlink | sysctl | missing |
| reverse DNS | `host` | `host` | missing |
| sandbox | Landlock + caps | stub | stub |

1. Connection states are matched against English `netstat` literals
   (`src/ui/connections.rs:134,1001,1128`; `connections.rs:1118` passes the
   raw token). German Windows reports `HERGESTELLT`; result is zero
   established connections. Same class as #39 and #40.
2. `ipconfig /all` parsing keys on `"Ethernet adapter"`, `"Wireless LAN"`,
   `"Media disconnected"`, `"IPv4 Address"` (`src/platform/windows.rs:139-
   150`). On a German system the adapter name becomes `Ethernet-Adapter
   Ethernet`, which then fails the GUID lookup added in 0.30.4. `config.rs:159`
   keys on `"DNS Servers"`, so no DNS probe. `windows.rs` has zero tests and
   no fixtures exist for any Windows parser.
3. `tracert` output is unparseable for sub-millisecond hops (`<1` fails the
   float parse, `src/collectors/traceroute.rs:343-349`).
4. Every tick spawns PowerShell (300-800 ms) plus `netstat` and `tasklist`;
   1 Hz is not achievable. `collect_interface_info` runs on the UI thread
   every 10 s (`app.rs:1441`) and forks `ip addr show` once per interface
   on Linux, so 50 Docker veths is 50 forks.
5. Linux with no `ss` shows nothing: `connections.rs:786` leaves the list
   empty although `/proc/net/tcp*` is already parsed at `:966`.
6. No `windows-sys` dependency; IP Helper (`GetIfTable2`,
   `GetAdaptersAddresses`, `GetBestRoute2`, `GetExtendedTcpTable`) would
   replace every shell-out above with locale-free native calls.

## 4. Privacy defaults

1. Every public peer IP goes to an online GeoIP service in cleartext (removed in 0.39)
   (`src/collectors/geo.rs:254-258`), triggered from render and the egress
   tick, gated only on `geoip_db` being empty. Rate-limited, private ranges
   excluded, no HTTP timeout, no opt-out short of installing MaxMind,
   documented in one clause at `docs/REFERENCE.md:509`.
2. `egress-profiles.json`, the process-to-host map, is written with umask
   permissions (`src/collectors/egress.rs:1035-1067`) while the policy file
   beside it enforces 0600 (`egress/policy.rs:262-281`).
3. Clean: child commands use fixed argv with no injection path; decrypted
   TLS plaintext stays in memory and never reaches pcap export or the
   incident bundle; logs carry no payloads; remote mode is client-only with
   a bearer token, HTTPS optional. The eBPF object is a prebuilt blob in
   `netwatch-sdk` with no source or hash in the crate.

## 6. Nobody can tell what is wrong

1. No preflight. `main.rs` has no doctor or check command; `App::new`
   starts capture unconditionally (`app.rs:736`) and the only failure text
   is "Permission denied — run with sudo" or "Capture failed: {e}"
   (`packets/mod.rs:1375-1381`), rendered in the Packets header alone
   (`ui/packets.rs:219-229`). An unprivileged user on the Dashboard sees
   empty rate columns and nothing else. Issues #38, #40, #47, #48, and #51
   are all "what is broken and why" reports.
2. Help drift. Hidden from help: `M` memory overlay (`app.rs:3137`), `v`
   (`:3196`), `f` filter cycling (`:3433-3458`), `G` grouping (`:3445`),
   Packets `y` and `d` (`:3755,3761`), the settings overlay including `S`
   save (`:2855-3020`). Stale in help: PgUp/PgDn (`help.rs:236`) with no
   handler; `S` described as picker-reverse (`help.rs:254,437`) but flips
   sort globally (`app.rs:3636`); "DASHBOARD (Tab 1)" printed twice with
   different bodies (`help.rs:240-248`, `260-277`).
3. Docs describe the pre-0.30 tool. `docs/WIKI.md:24-34` lists nine tabs
   with an Insights tab and says support is macOS plus Linux;
   `docs/INSIGHTS.md:3,29` says press `8`; `architecture-tour.html` says
   nine tabs; `DESIGN-0.30.md` cites `renders/` and a spec not in the repo;
   `config.rs:52` lists a `light` theme that maps to `paper` and omits
   three real ones. `egress-linter-plan.md` and `quic-decryption-plan.md`
   are executed worklogs linked from the README as user docs.
4. Half the CLI is undocumented: `daemon`, `--remote`, `--api-key`,
   `--metrics`, `--demo`, `--generate-config`, `--no-sandbox`
   (`main.rs:30-48,79-84,144-161`). The README under-claims QUIC 1-RTT
   decryption and HTTP/3 reassembly (`dpi/quic.rs:369`,
   `dpi/http3.rs:336-408`), connection JSON and CSV export, egress NDJSON,
   incident bundles, and the Prometheus exporter. It over-claims "ss/lsof on
   every platform" and a wifi rule that is Linux-only.
5. Community. 32 issues, median 20.8 h to close, six external PRs all
   merged same day. Seven of 32 issues are install or distribution, three
   are Windows capture. #27 (memory leak) was closed while the reporter's
   last figure was "174.3 MB, still climbing". Discussions are enabled and
   unused; issue templates are legacy markdown.

## 7. Architecture drag

1. `app.rs` is four things: view-model enums (`:83-400`), collector
   lifecycle and tick scheduler (`:685`, `:1414`), a 640-line key switch
   with 95 arms (`:3129-3769`, settings `:2807`, mouse `:2389`), and
   diagnose orchestration (`:4815-5044`). The key handler reaches into
   renderer modules 20 times for selection state.
2. Four connection view-models are built per frame from one
   `Vec<Connection>`: `ui/dense/mod.rs:660`, `ui/dashboard.rs:863`,
   `ui/connections.rs:557`, `ui/lite.rs:311`, each with its own host
   splitter, `truncate` (eight copies), and `put`. Only `ui/tree.rs::group_by`
   is shared. Charts are not duplicated; `graph.rs` is the single engine.
3. `platform/` abstracts only stats, info, route, link speed, and process
   name. Connection enumeration, DNS and gateway, ping, traceroute, and
   tcp_info all cfg-branch inside collectors (56 sites).
4. Concurrency is coherent: one thread per collector, `Arc<RwLock<Arc<T>>>`
   snapshot swap, busy-flag debounce, blocking work outside locks, no lock
   cycles. Headless mode already exists (`app.rs:1942`); a `--json` mode is
   blocked only by `Rect` and `Color` in `state.rs` and UI branching in
   `tick()`.

## Plan

**0.30.5, hotfix (about two days).** QUIC bounds checks with RFC 9001 A.2
mutation tests. Landlock with `all_threads(true)` where TSYNC is available,
applied before capture starts, and `catch_unwind` around `classify_once`
that clears `capturing`. `safe_lock` on the stream tracker with a drop guard
for `busy`. Re-mark the nine stub rules `Planned` and fix the label test.
0600 on `egress-profiles.json`. Correct the sandbox header comment.

**0.31, trust (two to three weeks).** `netwatch --doctor`: pcap or Npcap
load, CAP_NET_RAW and CAP_BPF, eBPF loadability, Landlock ABI, config
path, and the exact `setcap` or installer fix. Capture errors on the global
status strip. Implement `consecutive_n` in `Engine::merge`; dedupe baseline
readings to one per probe; window `total_retrans` over 60 s; gate
bufferbloat on RTT versus idle baseline. cargo-fuzz targets for every DPI
parser and checked-in pcap fixtures. SHA256SUMS in the release. A Windows
CI job that installs Npcap and runs `--doctor`. Docs sweep: rewrite or
delete WIKI and INSIGHTS, add a CLI and environment section to REFERENCE,
generate `help.rs` from one keymap table, fix `package.nix` and
`config.rs:52`. Lead the README with `--demo`. Reopen #27 and publish a
24-hour memory figure.

**0.32, Windows native.** IP Helper through `windows-sys` for stats, link
speed, adapters, default route, connections, and process names. Locale
fixtures (German, Japanese) for whatever parsing remains. `/proc/net` as
the primary Linux connection source with `ss` as an enricher. `getifaddrs`
instead of the `ip addr show` loop, moved off the UI thread.

**0.33, Diagnose depth.** Resolver backends per OS (`resolvectl`,
`networksetup`) behind `Action::SetResolver`, backups in the cache
directory, `make_permanent` on a key. Periodic 60 s re-trace and an
alternate-resolver probe to unlock the path rules and DNS cause ranking.
`netwatch diagnose --json` on the daemon loop. Then extract `ConnRowModel`
and split `app.rs` into `keys`, `diagnose`, and `filters`.
