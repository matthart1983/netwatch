## 0.32.4 — security hotfix (≈2–3 days)

Branch from `v0.32.3`, not `diagnose-enhancements`, so the fix doesn't wait
on unfinished work. Then cherry-pick it forward. Only item 1.3 touches
`packets/mod.rs`, which has PCAPNG work in progress. Keep that diff small.

### 1.1 Sanitize network strings before the TUI (High)
Peer-controlled strings reach ratatui raw. ratatui 0.27 keeps zero-width
characters in the cell, and the terminal prints them. A ClientHello with SNI
`\x1b]52;c;…\x07` writes the viewer's clipboard.
- Add a `ui::sanitize::display(&str) -> Cow<str>` helper. It replaces C0/C1
  controls, DEL, bidi overrides (U+202A–202E, U+2066–2069) and zero-width
  characters with `\u{FFFD}` or `·`.
- Apply it at *ingest* for every DPI-derived string: SNI (`dpi/tls.rs:165,240`,
  `packets/mod.rs:2633`), HTTP Host/path (`dpi/http.rs:106`), SSH banner,
  DNS qname, MQTT and SNMP strings, rDNS/whois/geo results, process names.
  Apply it again in the connections, packets, dense and dashboard render
  paths as a backstop.
- Replace the one-off sanitizer at `ui/packets.rs:426` with the helper.
- **Test:** one unit test per parser that feeds an ESC/BEL/U+202E payload,
  plus a `TestBackend` render test asserting that no cell symbol contains a
  control character.

### 1.2 Bound what an attacker can grow (Medium)
- **rDNS** (`collectors/dns_cache.rs:96,102`): cap the pending set, e.g.
  4096 entries with LRU eviction. Use a bounded channel and drop on full.
  Skip PTR lookups for addresses outside observed flows with our own
  endpoint.
- **HTTP/3 bodies** (`dpi/http3.rs:315,321,327`): wrap each decoder in
  `.take(LIMIT)`, e.g. 4 MiB, and mark the body truncated. Try brotli only
  when `content-encoding` says br.
- **Stream store** (`packets/mod.rs:17,22,830`): add a global byte budget,
  e.g. 256 MiB, with oldest-stream eviction. Make `get_stream` return a
  window or an `Arc` rather than cloning the whole stream every frame.
- **Metrics endpoint** (`metrics.rs:177,196`): cap the request line at
  8 KiB, set a 5 s read timeout, and allow at most 16 concurrent connections
  (refuse beyond that). Warn at startup when bound to a non-loopback address
  without auth.
- **ureq timeouts** (`remote/mod.rs:308`, `geo.rs:298`, `whois.rs:159`):
  use one shared agent with 5 s connect and 10 s read/write timeouts. Put a
  deadline on `final_drain`.
- **Test:** a unit test at each cap. Add a slowloris test against the
  metrics listener.

### 1.3 Survive a capture-thread panic
- Replace `stream_tracker.lock().unwrap()` (`connections.rs:388`,
  `packets/mod.rs:1987-1989,1998-2000`) with
  `lock().unwrap_or_else(PoisonError::into_inner)`.
- Wrap the capture loop in `catch_unwind`. On a panic, set
  `capturing = false` and record the error so the UI shows "capture stopped:
  internal error".

### 1.4 Small exposure fixes
- Refuse an `http://` remote URL unless `--insecure-remote` is given
  (`remote/mod.rs:309`).
- Mark `--api-key` as deprecated in `--help` in favour of `NETWATCH_API_KEY`
  (`cli.rs:116`).
- Create the exports directory as 0700 and write pcaps and incident bundles
  as 0600 even without the sandbox (`main.rs:88`, `pcap_export.rs:10`,
  `incident.rs:670`).
- Geo over HTTPS where the provider allows it (`geo.rs:295`). Otherwise say
  "cleartext" in the setting's label.

### 1.5 Release guard (do this first, before tagging 0.32.4)
- `release.yml`: add a first job that waits for `ci.yml` to succeed on the
  tagged SHA (`gh run list --commit $SHA --workflow ci.yml`, fail unless
  success). Make every other job `needs:` it.
- The same job fails unless `v$(cargo metadata version) == $GITHUB_REF_NAME`
  and the CHANGELOG has a matching `## [x.y.z]` heading.
- Extend `tests/packaging.rs` to cover `package.nix`, then bump `package.nix`
  from 0.26.1 with its hash.
- Add `scripts/release.sh X.Y.Z`. It bumps Cargo.toml, the RPM spec, nix and
  the CHANGELOG, runs `cargo test`, and then tags. That removes the hand
  edit that produced the stray v0.33.0 commit.

**Exit:** a tag on a red SHA fails before publishing, and all of 1.1–1.4
have tests.

## 0.33 — Diagnose credibility (≈1.5–2 weeks)

The six `[Unreleased]` fixes ship here. What's below is still open. Every
item needs a replay-corpus episode or a detector test that fails before the
fix.

### 2.1 Stop verdicts built on evidence not gathered
- **`dns.slow_resolver`:** `alt_rtt_ms` is always `None` on the live path
  (`diagnose/live.rs:687-691`), yet the `local_udp_path` cause records a
  *pass* saying "both resolvers are slow" (`detectors.rs:~1878-1892`). Mark
  that check NotRun when alt is None. Then add the passive alternate-resolver
  probe, timing one query to the second configured resolver or 1.1.1.1 per
  cycle, so the check can run.
- **Probe target:** query a random uncached name under a zone we control, or
  a random `*.example` query that gets an NXDOMAIN, rather than root NS. This
  measures recursion, not just the network round trip, so `upstream_slow`
  can be distinguished (`health.rs`).
- **`diagnose run` exit 0:** count gateway evidence only when loss is
  *measured* (`run.rs:199`, `health.rs:~304`). Exit 1 only when an issue is
  at or above a severity floor (default Low); report Info issues but don't
  let them decide the exit code (`run.rs:52`). Stop `--target` from
  filtering out host-wide root causes (DNS, gateway).

### 2.2 Make issues close
- Implement `auto_close_secs` (`engine.rs:154`). Close as "expired, evidence
  gone" when the rule's evidence has been absent that long. This covers
  sockets that went away (`retrans_burst`, `zero_window`,
  `bufferbloat_remote`).
- Make `dns.slow_resolver`'s verify condition relative: p50 back within 2σ
  of the baseline, or under the open threshold minus hysteresis. Drop the
  absolute 5 ms (`rules.rs:763`).
- **Corpus:** add episodes where each of these issues opens *and* closes.

### 2.3 Fix per-rule traps
- **`path.rtt_spike`:** learn a baseline per trace target (`live.rs:235-238`).
  Never fall back to the "internet" (1.1.1.1) baseline for another target
  (`detectors.rs:1989-1991`, `engine.rs:1235`). No baseline means NotRun.
- **`dns.failing`:** move the 5% literal into `Thresholds`
  (`detectors.rs:1501`). Require at least N=10 queries across cycles before
  judging, or a ≥2-of-3 streak over 3 cycles. Implement or remove the
  catalogue's "pipeline dns stage fails" branch (`rules.rs:89`).
- **Baseline σ floor:** add `max(σ, floor)` in `baseline.rs:200-206`, with
  floor = max(0.5 ms, 5% of mean). Feed the baseline non-overlapping p50
  windows rather than the rolling median on every probe.
- **`tcp.bufferbloat_remote`:** when `link_test_passed == Some(false)`,
  attribute the queue to our own uplink and use the uplink remediation text
  (`detectors.rs:2375,2436-2447`). Expire the test result after 10 minutes
  or on a network change. Align the catalogue (`rules.rs:296`).
- **`tcp.retrans_burst`:** judge a retrans *rate*, e.g. retransmits per
  segments sent ≥ 1%, rather than 5 per minute. A missing rtt is unknown,
  not 0. Drop the exclusion of sockets at ≥100 ms. Give "receiver-limited"
  its own rule id instead of reusing `tcp.zero_window`
  (`detectors.rs:156,~2507`).
- **Link rules:** watch the interface holding the default route, not the
  capture interface (`live.rs:389-391`). `link.down` on a non-uplink
  interface is at most Info.
- **Thresholds:** load `Thresholds` from config (`app.rs:512`). Add a test
  with non-default thresholds so the plumbing added in `[Unreleased]` is
  exercised. Add a test for the `dns.rtt_p50` baseline fix
  (`live.rs:217-224`).

### 2.4 Remediation honesty
- The TUI offers "writes resolv.conf…" but always records "not applied"
  (`app.rs:5465-5474`, `detectors.rs:~1943-1955`). Either hand off to
  `netwatch resolver set --unmanaged` with the exact command shown, or change
  the step text to "run: …".
- Propose a resolver only after measuring it (2.1's probe). Don't just take
  the second configured server.
- Delete `apply_file_edit`/`make_permanent` (`remediation.rs:317,392`), or
  make the CLI path use them. The CLI path writes in place: switch it to
  write-temp-then-rename so a SIGKILL cannot leave a half-applied file.

### 2.5 Split Diagnose out of `app.rs`
- Move the Diagnose orchestration and remediation (`app.rs:874-1370,
  5365-5578`) into `diagnose/controller.rs`, with App holding one field.
  This is the first cut of the `app.rs` split (4.1) and keeps 0.33's diff
  reviewable.

**Exit:** the fault lab drives the engine (not the `diagnose_probe` example)
for at least DNS slow/failing, gateway loss and path spike. The corpus has
open→close episodes for every rule touched. No detector reads a hard-coded
`None` as evidence.

## 0.34 — Windows, first run and docs (≈2 weeks)

### 3.1 Windows correctness
- Fix the traceroute parser (`collectors/traceroute.rs:408-436`): handle
  `<1 ms`, `*`, and "Request timed out." Add fixture tests from real English
  and German tracert output.
- Replace netstat/ipconfig/PowerShell with IP Helper via `windows-sys`:
  `GetExtendedTcpTable`/`GetExtendedUdpTable` (connections with PID, numeric
  state, no locale), `GetIfTable2`/`GetAdaptersAddresses` (interfaces),
  `IcmpSendEcho2` (ping, so localized Windows gets latency again,
  `health.rs:897,1081`). Remove the per-tick PowerShell
  (`platform/windows.rs:17,278,296`).
- Add unit tests for `platform/windows.rs`. Add a CI step that runs the
  release binary with `--version` and `doctor --json` on windows-latest.

### 3.2 Linux and macOS gaps
- Add a `/proc/net/{tcp,tcp6,udp,udp6}` fallback when `ss` is missing,
  reusing `proc_net_inode_index` (`connections.rs:1186`). `doctor` reports
  a missing `ss`.
- macOS: replace `lsof -i -n -P` per refresh (`connections.rs:819`) with
  libproc `proc_pidfdinfo`, or at least throttle it and cache it by pid.

### 3.3 First run without privileges

- Wrap `doctor`'s text on word boundaries.

### 3.4 Docs and help drift

  `c`/`d`/`t`, Egress `H`, Packets `y`/`d`, and global `M`. Add a test that

- Map `default_tab = "egress"` (`config.rs:308-320`).
- Fix `CAPABILITIES.md:75,94`, `WIKI.md:9`, `architecture-tour.html:153,192`.
- Add a README section for daemon, `--metrics`, `--demo`, `--remote` and
  `diagnose run`.
- Fix the `--help` column alignment (`cli.rs:43-50`).

### 3.5 FreeBSD (#57)
